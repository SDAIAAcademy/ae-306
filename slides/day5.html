What you build

Qafila's margin mart, from the raw extracts to an Iceberg table

  • Ingest the API and the change feed; supplier history as type 2.
  • Model a star at order-line grain, cost as of the order date.
  • Test and reconcile with finance's five answers.
  • Gate each batch with the contract: a broken one changes nothing.
  • Store the mart as Iceberg, read by a second engine.
  • Govern the fields: register, masking, access tests.
Starter: labs/capstone/pipeline.py has the eight steps, each naming the lab it reuses. The first is done.

Each bullet is one lab they have already done: 2.1 and 2.3 for ingestion, 3.1 and 3.2 for the model, 3.3 for the gate, 3.4 for orchestration, 4.1 for Iceberg, 4.4 for governance. The capstone is the first time the pieces run in one pipeline, in order, on one database. The trainer's reference solution is labs/solutions/capstone_pipeline.py: it runs end to end in about 25 seconds on a laptop and passes 13 tests; do not share it before the defences.

Reproducibility

The assessor clones your repository and runs it twice

git clone <your repository> && cd <it>
uv sync
uv run python pipeline.py
uv run python pipeline.py --batch broken
RunMust show
Fixed batchrow counts and test results equal to your README
Broken batchthe contract's failed checks, and the mart not refreshed
Second runno new rows from the API
Clone it yourself first, into a new folder. A file only on your laptop fails the run.

The two most common failures in a clean clone are a path that only exists on the author's laptop and a generated file that was never committed or that should have been generated. Ask them to test the clone before lunch, not after. Compare the row counts the run prints with the table in their README: a mismatch costs reproducibility points even if the mart is right.

Every number in the README comes from a committed run report. A claim without one is a plan, not a result.

Full marks on correctness means the five finance answers reconcile within one riyal and the fact has exactly one row per order line. On ingestion, a second run adds nothing and no supplier has overlapping validity ranges. On orchestration, the run log of the broken batch shows the failed checks and that the mart was not rebuilt, and a backfill of the month after the fix. The repository is 60% of the course result and needs at least 60% on this rubric; the defence is 20% and the supervised checks the other 20%; the pass mark is 70%.
